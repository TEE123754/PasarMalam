# PasarMalam — prototype demonstration checklist

Updated **9 October 2026** after the owner clarified the product is a prototype. The objective is to demonstrate potential future implementation/integration using visibly fictional examples. Real authority access, recognised certification, actual endorsements, real sales history and participant recruitment are **future rollout requirements, not prerequisites for this demo**.

The existing [151-item checklist](CONSOLIDATED_FEATURES_CHECKLIST.md) retains its real-evidence qualifications: 126 checked locally / 25 deferred future requirements. The checklist below describes delivered prototype behaviour. It does not turn simulated evidence into actual approval or validation.

## Demonstration features

- [x] Separate customer/hawker experiences, instant public customer signup and protected connected roles.
- [x] Market discovery, map pins, day/night/farmers classifications, schedules and directions.
- [x] Category, dietary, budget, distance, review and promotion filters.
- [x] Stall/menu photos, batch photos, independent batch numbers and original timestamps.
- [x] BM/English/mixed-language voice or text drafts, clarification, readback and explicit confirmation.
- [x] Advisory warnings, hawker-approved clearance, stock/collection gating and expired-offer removal.
- [x] Reviews, confidential reports, moderation and hawker replies.
- [x] Global **FICTIONAL — DEMO ONLY · REKAAN** label and persistent watermark on demo screens.
- [x] Original generic icons and typographic marks; no real authority logo, seal or signature.
- [x] Simple partner gallery: invented health office, municipal council and certification reviewer; no workflow controls.
- [x] AI-generated professional fictional authority identity and realistic invented creator campaign, both watermarked.
- [x] Customer food safety/handling complaints route to the demo health office; hygiene/pest complaints route to the demo council.
- [x] RasaTrail Demo promotion and linked stall picks help customers discover more hawkers.
- [x] Editorial endorsement remains distinct from paid sponsored placement and food certification.
- [x] Sample permit and halal certificate show fictional issuer, scope, expiry and supporting references.
- [x] Vendor declaration and recognised-certification concepts remain distinct in the mock-up.
- [x] Two certificate samples in the showcase; five authored proof artifacts remain available in the output folder.
- [x] Fictional issuer, scope, reference, scenario dates, limitations and supporting evidence shown.
- [x] Each supporting record can be inspected and exported with fictional origin metadata.
- [x] Current/expired/revoked/missing status examples; invalid proof hides the sample customer badge.
- [x] Case closure and collection receipt cannot become a certification badge.
- [x] Local proof links; no claim of live issuer verification.
- [x] Watermarked HTML documents, JSON proof packets and individual evidence exports.
- [x] Five ready-to-open HTML documents and five complete proof JSON samples saved in [the proof folder](../output/prototype-proof/README.md).
- [x] Synthetic forecasting responds to entered planned portions while preserving the frozen benchmark.
- [x] Forecast uncertainty, chronological baseline errors and fictional history remain labelled.
- [x] Actual AI request measurements remain available separately in Evaluation.
- [x] Existing fictional payments, sponsorships, advertising, collection receipts and impact dashboards remain available.
- [x] Android/iOS experience frames, notifications and unavailable-service fallbacks remain previews.
- [x] Showcase links connect the working product and future integration/proof journeys.

- [x] Review-tab complaint entry, displayed authority destination and simulated referral receipt retained with saved customer reports.

## How to show it

Open [Prototype potential](http://127.0.0.1:5174/demo/potential). Show the authority partner cards and creator campaign, inspect sample certifications, then submit a fictional food safety or hygiene complaint in the customer view. Expand evidence references and download a watermarked document. Use the feature directory to continue into the existing working app screens. Role-switching workflows and research exhibits were removed from the showcase at the owner’s request.
